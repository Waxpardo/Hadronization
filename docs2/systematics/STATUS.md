## One contradiction inside the variation selectors

Each of the seven `config/dataset_selector_hf_sys_*.json` files cites
`docs/SYSTEMATICS_PREREGISTRATION.md` and its sha256 as
`publication_authorization` / `publication_authorization_sha256`, and then
states five lines later that "publication_eligible is false and no
authorization is cited, deliberately". Both halves are generated by one
function, `tools/add_variation_selector_rows.py`, which writes the citation and
then writes the interpretation that denies it. The same clause appears in
`config/dataset_selector.json` for each of the seven rows: fourteen sites in
all.

**The clause is what is wrong, not the citation.** The document those rows cite
is the PRE-REGISTRATION that designed the variations, not a publication
authorization. `tests/test_dataset_selector_row_agreement.py` depends on the
rows citing something verifiable, so the citation must stay. The sentence was
copied from the `hf_smoke3` row, where authorization and sha are both null and
it is true.

The repair is a generator edit inside the paused module and waits for the
reactivation (ledger DA1-A047). Read the rows through this note.
