# Render — the plot launcher and its configurations

## The two commands

```
./hadronization plot-slot hf_run3_v1_candidate
./hadronization plot hf_run3_v1_candidate <TARGET> [TARGET ...]
```

`plot` resolves the dataset, prepares the output plane, then runs
`plotting/run_paper_plots.sh` with the targets it was given
(`hadronization:473-475`).

## The plot-slot binding gate

`plotting/Plots` is one checkout-local symlink. Its target is scoped per
campaign and per commit:
`$HADRONIZATION_RESULTS_ROOT/$HADRONIZATION_CAMPAIGN/<12-char commit>/plotting`
(`hadronization:96-98`).

One deploy therefore holds the slot for one run at a time. When the link exists
and points somewhere else, `prepare_plot_output_plane` **refuses and changes
nothing**, naming both targets and telling the operator to run `plot-slot`
(`hadronization:101-109`). An implicit repoint would move a render into another
campaign's tree, which is why the refusal stays.

`plot-slot` is the only thing that repoints the link. It moves the old pointer
aside under `plotting/Plots.<CAMPAIGN>-<COMMIT>.superseded-<DATE>`, prints both
targets, and deletes nothing; the target directories are untouched, so a sealed
run's files cannot be reached by a migration
(`hadronization:44-48`, `:121-131`).

A non-symlink at `plotting/Plots` is checkout-local output state and is also
refused (`hadronization:110-113`).

## Targets are explicit. `all` does not run this campaign

**`all` is not runnable for `HF_RUN3_V1` without an explicit
`THNSPARSE_CONFIG`** (finding F57). `all` expands to
`freeze-boundaries thnsparse multiplicity-boundaries kinematic-spectra`
(`plotting/run_paper_plots.sh:241-243`). The `thnsparse` target derives a
configuration named after the resolved campaign, and
`configuration_multiplicity_HF_RUN3_V1_THREETUNE_THnSparse.json` does not exist,
so `all` exits 2 at preflight (`:225-240`, derivation at `:457-459`).

The paper figures are therefore invoked **by explicit target**: G1 is
`multiplicity-spectrum` and G9 is `kinematic-spectra`, and `all` expands to
neither G1 nor any balancing configuration. That is the invocation rule, not a
defect to route around. Widening the expansion would be tidiness; it would not
make `all` runnable on its own.

`README.md:57` still writes `./hadronization plot hf_run3_v1_candidate all` in
its example chain. Read that line as illustrative of the command shape, never
as the paper-render recipe.

## The two raw-reading targets

`multiplicity-spectrum` and `kinematic-spectra` read raw files, not the merged
analysis product (`plotting/run_paper_plots.sh:418-421`). They need a raw base,
and there is no default behind it: with neither `KINEMATIC_RAW_BASE` nor
`HADRONIZATION_RAW_BASE` set, the run refuses and names both
(`:479-486`). The removed fallback pointed at the legacy pre-rebuild sample, so
a route that reached it would have drawn a publication figure from the wrong
sample without saying so.

Every other configuration path is derived from the resolved campaign and never
defaulted (`:386-397`). The defect that closed: `THNSPARSE_CONFIG` and
`THNSPARSE_COMPLETE_ROOT_CONFIG` once defaulted to the reduced JUNCTIONS
configurations, so a campaign with no configuration of its own rendered against
a file that is not its analogue.

## The five V-configurations

All five are generated by `tools/make_variant_configs.py`. Each writes to one
directory, and each global canvas carries the delivery name
[DELIVERABLES.md](../paper/DELIVERABLES.md) lists.

| configuration | `write_path` | global `write_name`s |
|---|---|---|
| `…_VINTEGRATED.json` | `plotting/Plots/VariantIntegrated` | `global_balancing_plots_integrated_beauty`, `…_charm` |
| `…_VEXTREMES.json` | `plotting/Plots/VariantExtremes` | `global_balancing_plots_multiplicity_beauty`, `…_charm` |
| `…_VBARYONMESON.json` | `plotting/Plots/VariantBaryonMeson` | `global_balancing_baryon_over_meson_ratio_multiplicity` |
| `…_VCORRELATIONS.json` | `plotting/Plots/VariantCorrelations` | one composite; G2 and G3 come from the hard-coded correlation canvas, not from this name |
| `…_VINTEGRATED_CLOSURE.json` | `plotting/Plots/VariantIntegratedClosure` | one composite; this configuration exists to be verified, not delivered |

`tests/test_delivery_names.py` pins the five delivery names, asserts one
`write_path` per configuration, and asserts that no mini canvas is named by two
globals. That last check is not decoration: the macro holds one `TPad*` per mini
name and `Draw()` re-parents it, so a mini named by two globals renders on the
last canvas and leaves the first blank with no error
(`tests/test_delivery_names.py:16-20`).

V-CORRELATIONS is the only tracked paper-campaign configuration with
`draw_correlation_plots: true` (finding F59; verified across all seventeen
tracked plotting configurations). Its correlation canvas writes to the
hard-coded directory `plotting/Plots/THnSparse/Correlations`
(`plotting/improvedPlotting_THnSparse.C:4239-4241`).

**One render per stem per session.** Promotion from the staging directory is
`::rename` (`plotting/StagedOutputs.h:123`), which overwrites silently. A second
render of the same stem replaces the first with no record.

## The closure configuration stays narrow, deliberately

Ruling R40 widened the **figure** configurations to two trigger groups and the
legacy associate set. It did not widen the **closure** configuration, which
stays on the base four series — B⁺→B⁻, B⁺→Λ_b, D⁺→D⁻, D⁺→Λ̄_c⁺
(`tools/make_variant_configs.py:165-182`).

The reason is that the closure and CONTROL instruments verify the class axis
against the accepted J-c1.1 log, whose shape is 132 rows over twelve
identities. A widened closure derives 48 identities and a 576-row render — a
shape no accepted log carries — and the 144/132 contract stops being checkable
at all. The boundary receipts the closure certifies are shared by every figure
render, so the wider figure scope loses nothing here.
