## A9 — the answer is NO, and the evidence is specific

The table needs three things: events, the valence sums N_{b+b̄} / N_{c+c̄}, and
eight inclusive per-species yields. **Only the events exist.**

| artifact | what it actually holds |
|---|---|
| receipts | provenance only — shas, bytes, state. Zero physics |
| `validate_raw_output.log` | `RAW_ORIGIN_AUDIT` + errors/entries. Origin accounting, not yields |
| `attempt_metadata` | `requested_successes`, seed, shas, timing |
| `campaign_status.py` | attempt/receipt bookkeeping |
| M7 block logs | `ub/um/rb/rm` — **baryon/meson split, not per-species** |
| merged pair files | `hFlavourClosureSpecies` — trigger-owned and closure-**weighted**, not a yield |

**Two distinctions did the work here**, and both are why a plausible-looking
shortcut fails:

- **Hadron counts are not valence counts.** N_{c+c̄} is Σ|q_c|; a Ξ_cc
  contributes 2. M7's hadron totals cannot be rescaled into it.
- **A closure-weighted species table is not an inclusive yield.**
  `hFlavourClosureSpecies` is weighted by −q_trig·q_assoc and owned by the
  trigger. It answers a different question entirely.

**The attic macro cannot be re-pointed**: it reads `hidCharm`/`hidBeauty`/`hidBc`
and a `tree`, none of which exist in the current `hf_primary_ground_raw_v7`
schema. It is evidence of what was counted, not a route to counting it again.
