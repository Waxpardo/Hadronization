## 4. ITEM 3 — LANDED, two commits, suite green after each

### `73dbec7` — the version machinery (no object added; v2 unchanged)

`RequiredPairObjects`, `PermittedPairObjects` and the three closure selectors are
keyed on a `PairSchemaVersion`, resolved **per file** from its own
`analysis_schema` through `ParsePairSchemaVersion`, which **fails closed**.
Membership is an optional per-object `since_schema` defaulting to the oldest
version, so a v3 object touches one row rather than all 62.

> **FOUND AND REMOVED — a live instance of the very defect the design exists to
> prevent.** `ValidatePairDirectory.C` pinned
> `kRequiredAnalysisSchema = "paul_pair_objects_primary_ground_v2"` and compared
> against it ~200 lines below the object-set comparison. **A correct v3
> directory would have passed the allowlist and then been rejected by that
> literal.** A test now forbids any judging consumer from pinning the literal.

The ten-block closure resolves the schema once and **requires every later file
to agree** — a mixed-schema directory is not a closure and must not be summed.

> **ALSO FOUND — a silent false-green in the test harness.**
> `tests/test_pair_object_contract.py` invoked `main()` at its *midpoint*, and
> `main()` collects test functions from `globals()`. **Every test appended after
> that line was collected by nothing and reported as passing.** I hit it by
> appending tests and seeing them not run. The dispatcher now runs from the end
> of the file and **prints the count** (`tests=14`), so the same silence cannot
> recur unnoticed. **Check other test files for the same shape.**

### `0059905` — `hFlavourClosureSpecies`, v3-only

Header diff is **exactly** the one object plus the array size (62 → 63), mask
`0b10`. Proven by a C++ harness — the three required cases plus fail-closed
parsing:

- a correct **v2** directory expects six content objects and is **accepted**;
- a **v2** directory carrying the v3 object is **rejected** (the object is in
  neither v2's required nor its permitted set — **permissiveness was not the
  fix**);
- a **v3** directory missing it is **rejected**.

The harness is C++ on purpose: the header is what consumers compile against, so
a Python re-reading of the JSON would test the contract against itself.

> **THIS CORRECTS MY OWN v22 AUDIT.** I recorded that the one
> object-count-sensitive literal was already derived and needed no edit. That
> was right about the *literal* and **wrong about the derivation**: it summed
> every contract row **regardless of version**, so it would have demanded seven
> content checks from a correct v2 directory — the same class of error as the
> pinned 1500, one version later. The closure now **reports** the schema it
> adopted and the wrapper derives the count for it, filtering on
> `since_schema`. The other four literals are confirmed unaffected: three are
> file counts, and `additive_metadata_closure_checks` counts `additive_scalar`.

**Evidence:** suite **26/26**, pre-registered at 26/26. All three C++ consumers
