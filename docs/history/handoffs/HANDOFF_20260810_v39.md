### The integer-count design, ratified with its rationale

The production macro prints baryon splits only as **percentages to two
decimals**. Reconstructing counts loses **±10 candidates per file** ≈ 0.1 % of a
block total — **~20× the MONASH shift being measured**. So sums use exact
integers from a scratch macro reusing the production cut strings verbatim, and
the driver cross-checks that replication against the production macro on one file
per tune per block: **30 checks, all `XCHECK_OK`**.

column is a bound; no kinematic differential.
