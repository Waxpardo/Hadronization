### Why it stopped

**`effective_card_sha256` is sensitive to comment bytes.**
`tools/campaign.py effective_card_bytes()` reads `card.read_bytes()` and
substitutes only `Main:numberOfEvents` and optionally `PhaseSpace:pTHatMin`.
**It does not strip comments.** Therefore any comment edit changes the card's
recorded hash. That hash is:

- written into every rendered production submit row —
  `tools/render_production_submit.py:230,243`
- validated as a `HEX64` field — `tools/statistical_robustness.py:567`
- compared as a **plain `sha256(card)`** against a recorded per-tune value —
  `tools/evaluate_pthat_sensitivity.py:419`
  (`if sha256(card) != campaign.get("card_sha256", {}).get(tune)`)

**So a comment-only edit is a provenance change**, and any later comparison of a
re-rendered card against HF_PT2_INT's recorded card hash will fail. That is
"touches promoted data" and needs an explicit owner decision.

**`tools/validate_tune_cards.py:47` is NOT the obstacle** — it does
`raw.split("!", 1)[0]`, so it ignores comments entirely. **The obstacle is the
hash, not the validator.**

**`tests/test_submit_rendering.py:121-124` is not an obstacle either** — it
asserts the three cards' hashes *differ from each other*, which survives editing
all of them.

### The owner's options

1. **Accept the hash change.** Comments are the intended change; record in
   `RELEASE_BLOCKERS.md` that HF_PT2_INT's recorded card hashes predate the
   comment corrections and are expected to differ. Cheapest, and the
   information is worth more than the hash continuity — **but it must be
   written down or it becomes a mystery later.**
2. **Defer to the registry change.** The proposal already moves
   `upstream_executable_sha256` off `e54b27bb…`; folding card comments into the
   same provenance break costs nothing extra and breaks continuity once
   rather than twice. **My recommendation.**
3. **Normalise the hash** — strip comments in `effective_card_bytes`. **A code
   behaviour change, explicitly out of scope this session, and it would
   silently alter every future card hash.**

**The corrected comment text is ready to write the moment this is decided; all
its numbers are verified above.**
