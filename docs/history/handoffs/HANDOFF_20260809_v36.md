## 2. THE EXTRACTION READER — landed, and its cross-check is exact

`tools/extract_species_decomposition.py`, run against the anchor's 100-input
merged directory (a real v3 merged product).

```
EXTRACTION pairs=300 filled_species_ordinals=91 digest=646f310f78126267
 cat name                 from species     from closure      rel
   0 kCentralGround           67969216         67969216   0.00e+00
   1 kHiddenHeavy                    0                0   0.00e+00
   2 kMultiplyHeavy                 48               48   0.00e+00
   3 kOtherNoncentral                0                0   0.00e+00
   4 kExcludedVector          60600180         60600180   0.00e+00
   5 kExcludedExcited          1314400          1314400   0.00e+00
SELF_CHECK AGREE worst_relative=0.000e+00
```

**The self-check is the point.** The species table's `category` column
(`ClassifyHeavyStateDetailed`, at table-generation time) and the analysis's 6-bin
`heavyStateCategory` axis (the macro, at fill time) are computed
**independently**. Summing 202 species bins into 6 groups reproduces the closure's
own projection **exactly** — not to tolerance, to zero.

**The physics in that table is the first look at what the paper turns on:**
`kExcludedVector` carries **60.6 M against central ground's 68.0 M** — nearly as
much compensation sits in excluded vectors as in the central ground states. That
is the excluded-fraction problem the observable-definition sentence exists to
address, now resolved per species rather than argued.

**Fail-closed on two conditions**, both exercised: the in-file
`species_ordinal_digest` must match the artifact, and any filled bin outside
0..201 is a hard error — the axis has **no overflow bin by design**, because an
overflow bin is how 152 species became invisible in the first place.

**SEMs are not computed, deliberately.** They need the spread across ten
deterministic blocks per tune; one directory is one number per bin and a SEM from
it would be fabricated. `--blocks` **refuses**, with that explanation.

**Category names come from `category_counts` key order**, with a consistency
assertion against every species row — so `kHiddenHeavy` and `kOtherNoncentral`
appear as named zeros rather than being silently dropped. A decomposition table
that omits an empty category is the same failure mode the no-overflow rule
prevents.

**Decay-parent regrouping** (the experiment-comparable convention) still waits on
**F4's probe**; the diquark-structure grouping is what the category column gives
and is computable now. **F4 stays queued, not started.**

## 3. F3 STEP 2 — the diff, and the problem that would have ruined the table

`docs/F3_VIRTUAL_TRIGGER_CLOSURE.md`. Built as a **recorded diff** from the
`EXACT` baseline: `f3_runs/f3_virtual.diff`, **111 added lines, 6 removed**,
generated by a committed script so it is reproducible rather than hand-edited.

**Five edits. Four mechanical, one physics, one correctness:**

| | |
|---|---|
| **A** | read `heavyDaughter1/2` — production never reads them |
| **B** | register B*/Σ_b* (both charges) as triggers, sector `beauty` |
| **C** | **physics:** a virtual trigger is neither final nor a ground state, so `EligibleBase` rejects it by construction. Relax **exactly** `isFinal` and `FindGroundState`; keep central, direct-primary status, central kinematics |
| **D** | **correctness:** exclude the virtual trigger's own decay **descendants** from its compensation sum |
| **E** | report virtual triggers — the production `FLAVOUR_CLOSURE` print sits inside the loop that writes **pair files**, and virtual triggers have none |

> ### Edit D is the one that would have silently ruined the table
> **B* → B γ has ~100 % branching, and the daughter B carries the SAME b quark at
> the SAME sign.** The closure loop skips only the trigger itself, by
> `heavyIndex`. Without descendant exclusion, every virtual trigger would take
> **−1** from its own daughter — a systematic offset on every single one.
> Ground-state triggers never hit this because they are final and have no
> daughters in the record.

**And the self-check needs no external reference.** The macro logs
`full_phase_space` per trigger and it is **1** for ground states — the flavour sum
rule. **If edit D is right, virtual triggers must also give 1.** If it is missing
or wrong they give ~0. Edit E deliberately **does not throw** on a violation:
production throws because a violation there means lost flavour, but here **the
sum rule is the measurement** and the number must be visible, not fatal.

### Result: the harness works, the triggers do not fire — cause found

Final run `5400819`: `rc=0`, **301 files**, one summary, ground-state sum rules
all **1**, and `F3_VIRTUAL_CLOSURE` emits for all twelve PDGs. But:

```
F3_VIRTUAL_CLOSURE pdg=513  weighted_triggers=0 full_phase_space=0 ...
   ... all twelve identical ...
```

**Every virtual trigger has `weighted_triggers = 0`.** The cause is exact and the
fix is one line: edit C relaxed `isFinal` and `FindGroundState(pdg)` but kept
`(*heavyCentral)[triggerIndex]` — and the producer sets
`heavyCentral = (FindGroundState(id) != nullptr)`
(`heavyflavourcorrelations_status.cpp:1186-1187`). **`heavyCentral` IS
`FindGroundState`, precomputed**, so dropping one while keeping the other
relaxes nothing.

**Drop `heavyCentral` for virtual PDGs too**, leaving `IsDirectPrimaryStatus`
and `IsCentralKinematic` (the latter is genuine kinematic acceptance and stays),
then re-run and read `full_phase_space`: **≈1 ⇒ edit D is right and the table can
be built; ≈0 ⇒ it is wrong and no table should be produced.**

**Harness nit:** the success check asserts `files == 300`; the correct count is
now **301** (edit E adds `f3_virtual_triggers.root`), so the last run reported a
spurious `ABORT` on that alone.

**The table is not produced.**

## 4. THREE INVOCATION FAILURES, and what each one taught

All three were mine, all caught before any number was believed:

1. **Missing entry point.** ROOT calls the function named after the **file**; I
   renamed the patched copy to `f3_virtual_macro.C`, so it found nothing and
   fell back to `.L`. **`rc=0` with zero files** — the exit code lied. Fixed by
   keeping the production filename in the scratch tree.
2. **My success check was too weak.** It tested `rc != 0` only. The production
   runner checks for exactly one `ONE_PASS_ANALYSIS_SUMMARY`
   (`run_status_analysis.sh:272-276`) precisely because ROOT's exit code is not
   trustworthy. **I now check rc, summary count, file count, and error strings.**
3. **Double-escaping.** `"\n"` in a C++ string passed through two Python string
   layers and arrived as a **real newline**, producing an unterminated literal.
   Replaced with `std::endl`. My first two fix attempts also failed —
   `re.sub` treats `\n` in the *pattern* as a newline metacharacter even inside a
   raw string. `str.replace` was the right tool.

**A stale-output trap worth recording:** on failure #3 the check reported
`files=300` because the previous run's output was still there. **A file count is
not evidence unless the directory was cleared first**, and it is now.
