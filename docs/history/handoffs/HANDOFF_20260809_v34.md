## 2. M2 — SETTLED. The review is right, with one qualification

`docs/M2_PROBQQ1TOQQ0JOIN.md`. Read from the **pinned 8.317 source**.

**`probQQ1toQQ0join` is indexed by the heavier of the two quarks being joined
*into the diquark* — not the heaviest quark in the baryon.**

```
FragmentationFlavZpT.cc:523  makeDiquark(int id1, int id2, int idHad)
                       :526    int idMax = max( abs(id1), abs(id2));
                       :537    if (rndmPtr->flat() > probQQ1join[min(idMax,5) - 2]) spin = 0;
```

Index 0 = u/d, 1 = s, 2 = c, 3 = b. **Λ_c is `c + (ud)`, Λ_b is `b + (ud)` — the
diquark is `(ud)` in both, so both consume index 0.** The heavy quark sits at the
other string end and is never an argument to `makeDiquark`. **The review's claim
holds.**

**On the junction question, which the brief asked to settle explicitly:
junction and non-junction do NOT consume different entries.** Both call the same
`makeDiquark` with the same indexing. What differs is *which two quarks are
offered*:

- non-junction break: `FragmentationSystems.cc:337`
- **junction: `StringFragmentation.cc:2399` — `makeDiquark(idMin, idMid)`**, where
  `idMin`/`idMid` are the **remnant flavours after fragmenting the two
  lowest-momentum legs** (`:2344,:2347`; legs ordered by momentum in the junction
  rest frame at `:2112-2117`).

> **So a heavy quark *can* reach the diquark — but only in a junction topology,
> and only if it survives as the remnant end of one of the two lower-momentum
> legs.** The code establishes the path **exists**. **It does not establish how
> often it is taken; that is a measurement and the note asserts no rate.**

**Owner decision, no `Paper/**` edit.** The `Results.tex` premise survives for
the light-diquark case it describes; the qualification it may want is the
junction topology.
