### `baryonSup` and `doEnhanceDiquark` — traced in PYTHIA 8.317 source

Source at `/data/alice/ipardoza/pythia_stock_8317/pythia8317/src/`.

**`ClosePacking:baryonSup` is inert unless `doClosePacking = on`.**
`StringFragmentation.cc:701` reads it into `qqSupAnti`; used at exactly one
place, `:3192`, inside `kappaEffModifier`; that function is called at `:823`,
`:924`, `:2254`, **all three guarded by `if (closePacking)`**.
→ *"Set it to default" is NOT a control against MONASH — in MONASH it is dead
code and its 0.5 in the audit table is an unread default. Only a variation
within CLOSEPACKING is meaningful.*

It is also not a plain suppression knob. It is `f_q` in the **popcorn
destructive interference** term (xmldoc `ClosePacking.xml`, section "Popcorn
destructive interference"): `P'(qq:q) = (1−f_q)^{n_q/9}(1−f_p)^{n_p/9}·P(qq:q)`
(`StringFragmentation.cc:3195`). Raising 0.5→0.928 **suppresses** baryons more.

**`doEnhanceDiquark` is a separate axis pulling the opposite way.**
`FragmentationFlavZpT.cc:171-178` applies `kappaRatio = 1 + enhanceDiquark ·
kappaModifier` to `probQQtoQ` **only if `doEnhanceDiquark`**; `:187` applies
`probQQtoQ = probQQmod · probQQtoQ` **unconditionally**. Two independent
multiplicative routes onto the same quantity: κ-**enhancement** (gated, off in
CLOSEPACKING) and popcorn **suppression** (ungated, tuned up). Report them
separately; neither is independent of `doClosePacking`.

**Proposed measurement (owner's design, not yet run):** CLOSEPACKING at
reduced statistics with `baryonSup` 0.928 vs 0.5, packing on in both, reporting
how much of the enhancement moves. A systematic, not a fourth production arm.

## 12. Prohibitions and STOP discipline — carried forward verbatim

- **Never `git add -A`, `git add .`, or `git commit -a`.** A bare add once swept 25 MB of dev output into a commit. Stage explicit pathspecs only.
- **Never `git stash -u`.** It swallows the untracked `submit_*.sub` files.
- **Never touch `config/burned_seeds.txt`** except through `tools/campaign.py`. Gitignored, irreplaceable.
- **Do not move the Nikhef checkout while jobs run.** They verify the commit at startup (`runCondorJob.sh:143-147`) and mid-run (`run_status_analysis.sh:148-158`). This has cost 17 failed jobs, twice.
- **Never discover a cluster id with `condor_q -af ClusterId | tail -1`.** It has released an unrelated cluster. Parse `condor_submit` output.
- **Do not delete anything not on `docs/audit/deletion_candidates.txt`,** and nothing classified UNSURE.
- **Do not remove verification machinery.** Checksum pinning, seed ledger, card materialisation, schema constants and validators survived the gate purge deliberately. **If a fix seems to require weakening a validator, that is a STOP, not a decision.**
- **Out of scope:** `tools/statistical_robustness.py`, `tools/evaluate_pthat_sensitivity.py`. The first is load-bearing — `:602-610` validates the block files.
- **STOP discipline.** When a decision is the owner's, stop and ask; do not batch several STOPs into one question at the end. The owner's stated preference: *"I would rather answer four questions across four turns than approve a fait accompli."* Announcing a STOP and then proceeding without an answer is the failure mode to avoid.
- **Report honestly.** If a commit message claims something untested, say so. Two of this session's most useful moments were admitting a fix had been asserted rather than verified, and catching that a routine `git reset --hard` would have destroyed data.
