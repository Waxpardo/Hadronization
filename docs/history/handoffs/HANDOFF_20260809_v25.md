## 5. THE 12-VS-10 ACCOUNTING — closed, third-generation debt

Documented **beside the number**, in `validate_pair_block_closure.sh`.

```
10  contract-derived: ValidatePairBlockClosure.C:392-407 iterates
    ClosureCheckedScalars over both TParameter types = the contract's 10
    closure-checked additive_scalar objects
 2  hand-written at :522 and :530 -- input_file_count, source_input_events
--
12  per pair file x 300 = 3600
```

**Those two are correctly hand-written.** Both are `invariant`/`exempt`, so
neither is an additive closure; what the closure checks is a **mode-dependent**
relation — under all-event blocks the block sum equals the central value, under
modulo blocks it equals `kBlockCount ×` it. **No contract axis expresses "equals
the sum here, N times it there."**

**Follow-up recorded, not taken:** deriving them needs a new contract axis for
that conditional relation — not the same trivial shape as the derivations
already landed. The literal is safe meanwhile: v3 adds no `additive_scalar`
object.
