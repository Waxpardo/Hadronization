## 1. THE GUARD — the freeze is mechanism now, not memory

`tools/checkout_advance_guard.py`, wired as **`make can-advance`**. Run it on the
host with `condor_q` **before advancing the checkout by any means**.

**The invariant, stated so it cannot be re-misread:**

> **Jobs in flight that pin a commit ⇒ the checkout does not move.** Production
> verifies at **startup**, analysis at **promotion**. It is not a property of a
> campaign, and "the freeze is over" is only ever true of a *specific* campaign,
> and only until the next submission.

- **Refuses** while the queue is non-empty — **no threshold**, one job refuses
  exactly as 3000 do.
- **Refuses on UNKNOWN**, same fail-closed principle as `queue_probe.py`: an
  unanswered question is not an empty queue, and the cost of being wrong is
  re-running a campaign.
- **Override is for restoring a pin, not ignoring the guard**, and requires
  `--override-reason`, which is echoed into the output. `OVERRIDE` and `ALLOW`
  are distinct verdicts so logs can tell them apart.

**Seven tests, all on paths unreachable against a healthy cluster.** Verified
live in both directions: refused naming *"2702 job(s) in flight"*, and accepted
the detach override echoing its reason.
