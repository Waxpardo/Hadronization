a retry draws a *fresh* seed, so a residual far below 7 means hangs are
seed-specific, and near 7 means they track slow events. It costs nothing to
observe. **Record it.**

## 2. THE SPECIES AXIS — LANDED (`311a582`), both validations green

### Implementation

- **Four sites**, plus `hFlavourClosureSpecies` built by the **same constructor**
  as `hFlavourClosure`, parameterised only on the last axis. The other four axes
  are therefore identical **by construction**, not by two code paths trusted to
  stay in step — check 2 compares them bin for bin and would otherwise be
  meaningless. **`hFlavourClosure` is untouched.**
- **Ordinal loading is a generated header**, `AnalysisScripts/GeneratedSpeciesOrdinals.h`,
  not a runtime JSON read: the macro is ROOT-only and has no parser. It also
  makes the lookup fail-closed at compile time, gets staleness caught by
  `make check`, and means jobs need no artifact shipped beside them.
- **Fail-closed mapping**: a sector-charged PDG absent from the table aborts
  naming the PDG, its charges, the table size and its digest. **No overflow
  bin.**
- **v3 schema tag** moves in the same commit, necessarily: a file carrying the
  object while still declaring v2 would be rejected, correctly, by its own
  contract.
- **Legibility**: `species_ordinal_schema`, `species_ordinal_labels` (the
  ordinal → PDG map) and `species_ordinal_digest` are written to every output.

### Both checks, verbatim, on 300 fixture files

Analysis run end-to-end on the fixture, 100,000 events, ROOT-only, env vars per
2a. `ONE_PASS_ANALYSIS_SUMMARY inputs=1 source_events=100000 selected_events=100000 pairs_written=300 primary_all_heavy_closure_failures=0`.

**Check 1** — `FLAVOUR_CLOSURE ... full_phase_space=1` for every trigger; the
macro throws above 1e-9 and did not.

**Check 2**, per file, all 300 identical in form:

```
species_bins=915 compared=915 species_only=0 unmapped=0
```


**The fail-closed mapping never fired across 100,000 events**, so the
202-species table is complete against real JUNCTIONS data.

> ### CHECK 2 WAS WEAKER THAN IT LOOKED, AND WAS STRENGTHENED
> `category_bins == species_bins == 915` meant each category bin held **exactly
> one** species at fixture statistics — the correlation space is
> 100 x 100 x nPt x 4096, so filled cells are almost always singletons.
> **"Summing" was a copy; many-to-one addition went untested.** I added a
> category marginal that integrates the fine axes away, forcing up to **7013**
> ordinals into one category total. `worst_marginal_deviation=0.000e+00` across
> all 300 files. **The bin-for-bin number alone would have overstated what the
> check exercised.**

### The legibility trap, closed

v23 flagged that `invariant_metadata_checks=600` was **2 hand-picked objects**,
and that adding legibility objects without teaching the checker would repeat the
`hFlavourClosure` silence. Rather than hand-add three more names:

- a new **`identity_checked`** contract axis;
- the closure **derives** the set via `IdentityCheckedObjects(version)` and owns
  only the expected *value* per name (a compile-time constant, which cannot come
  from JSON), **failing loudly** if the contract marks something it does not
  know;
- the wrapper derives the count too — it would have gone stale at **1500** this
  commit.

**Also found:** `tests/test_pair_block_closure.py` pinned that same `600`. The
**test** held its own copy of a number that is a function of the contract —
B12's defect, in the test rather than the wrapper.

## 5. COLD-READ SELF-REVIEW

1. **The species axis has never run on MONASH or CLOSEPACKING data.** The
   fixture is JUNCTIONS. The ordinal table's selection is `open_heavy == 1` over
   PYTHIA particle data, which *should* be tune-independent — **I reasoned that,
   I did not measure it**, and I said the same in v23 without acting on it.
   Deriving the table from a MONASH raw file and diffing the digest is cheap and
   would settle it. **Do it before trusting the axis at scale.**
2. **No merged directory has been through the new closure or allowlist.** All
   three compile, the unit harnesses pass, and the fixture run exercised the
   *producer* — but the ten-block closure and `ValidatePairDirectory` have not
   run against real merged data since I changed them. The natural moment is the
   post-drain sync, and it should happen **before** trusting them.
3. **`additive_metadata_closure_checks = 3600` is 12 per file against 10
   `additive_scalar` objects.** Flagged in v22, again in v23, and again not
   chased. It is small, bounded, and still unexplained. **Third time it is being
   handed on.**
4. **The exact-zero deviations are almost too clean.** `0.000e+00` for content,
   Sumw2 *and* the 7013-term marginal means the additions reproduce bit-exactly.
   That is plausible — the same doubles added in a different order can still
   agree exactly when the terms are few or well-separated — but I did not prove
   it must be so. If a successor sees a small nonzero deviation on other data,
   **that is not automatically a defect.**
5. **I submitted and released 119 jobs late in the session.** They are flying and
   healthy, but I did not watch them long. **Check hold reasons early next
   session** — if the retry hangs at the attempt-0 rate the residual is ~7, and
   anything much larger deserves attention before round 2.
6. **The 5x correction rests on my own earlier error.** I would rather it had
   never entered the record. The general lesson is worth more than the number: a
   rate measured while a tune is still starting is not that tune's rate, because
   the guard's own threshold selects the slow tail.
