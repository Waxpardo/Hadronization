## 3. B15b — what was wrong and what it cost

**v1 `seed_for()` had no campaign term**, so every campaign at attempt 0 drew
the same sequence from `SEED_BASE`. HF_RUN3_V1 at ordinal 3 tried to draw seeds
the ledger labels `# HF_SMOKE attempt0`. **B2's `assert_seeds_unused` refused it
at render — nothing burned, no `.sub` written.** First production-scale test of
that guard; it is why this was a near-miss and not an incident.

**Retrodiction check before any code changed:** only two `seed_for` callers,
both forward. `campaign_status.py:73,95` **reads** stored seeds rather than
re-deriving. **No versioning needed; v2 replaced v1 outright.**

**v2:** `seed = SEED_BASE + ordinal*CAMPAIGN_STRIDE + tune*TUNE_STRIDE +
attempt*ATTEMPT_STRIDE + job`, `CAMPAIGN_STRIDE = 10_000_000`.
`campaign_ordinal` is **keyword-only, no default** — a default is how the bug
would return. `MAX_CAMPAIGN_ORDINAL` **derived = 79**; out-of-range **raises**.

### The audit overturned its own pre-registration

**Expected:** HF_SMOKE-era seeds collide with later attempt-0 campaigns.
**Measured: ZERO realised collisions in 430 entries** — because **the attempt
axis had already been used as a campaign counter**:

| campaign | attempts |
|---|---|
| HF_SMOKE | 0 |
| HF_SMOKE2 | 1, 2, 3 |
| HF_PT2 | 4, 5 |
| HF_PT2_INT | 6, 7 |

**Eight of ten attempt slots were consumed.** That converts the
rejected-alternative argument from semantic to arithmetic: **`SUBMIT_ATTEMPT=8`
would have left ONE slot** for a 3000-job campaign needing two-to-three retry
rounds — **production would have run out mid-flight.** v2 returns all ten.

**Disposition: documented, never repaired.** No ledger edit, no data action.
