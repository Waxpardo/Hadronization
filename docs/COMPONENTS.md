# Components — every executable in this repository, and why it exists

**Written 2026-08-17 by the triage pass, against `d5f96d3`. Suite 46/46.**
The navigable map of the code. [`ARCHITECTURE.md`](../ARCHITECTURE.md) explains
*what the project measures*; this explains *what each file is for*.
[`REMOVALS.md`](REMOVALS.md) records what left; [`RENAMES.md`](../RENAMES.md)
records what moved.

**Every entry here is a justification for keeping a file.** The pass asked one
question of all 219 tracked executables — *why does this exist?* — and a file
that could not be answered was removed rather than documented. Six were.

---

## 0. HOW TO READ AN ENTRY

```
`name` — one-line purpose                                            · status
  in → out
  ← called by      → calls
  why: the decision, defect or measurement that created it
```

| status | meaning |
|---|---|
| **pipeline** | on the generation → analysis → merging → extraction → plotting path |
| **measurement-provenance** | the recorded regeneration or verification path of a published number: a `GOLDEN_OUTPUTS.md` recipe, an anchor manifest, or a citation from the systematics programme |
| **test** | in `make check` |
| **operational tool** | campaign management, submission, guards, environment |
| **kept-not-live** | no consumer today, kept for a stated reason. Not a synonym for dead |
| **UNSURE** | the question is stated in §11. Six files, all location questions, none an existence question |

> **The rule this pass had to derive, and §12 explains why:** in this repository
> **a code filename is often load-bearing provenance.** 67 of 219 executables are
> named inside `GOLDEN_OUTPUTS.md` recipes, run records, anchor manifests, signed
> configs or the `Makefile`. Renaming one falsifies a reproducibility claim.
> Those names are frozen exactly as the artifacts are.

## 1. STAGE 1 — `generation/` — make the events

**`generation/producer/heavyflavourcorrelations_status.cpp`** · pipeline · **name frozen**
> tune card + seed → `raw/<TUNE>/hf_<TUNE>_jobNNN.root` (100 k events, schema `hf_primary_ground_raw_v7`)
> ← `generation/submit/runCondorJob.sh` → `HeavyFlavourUtils.h`, `Sha256.h`, both registries
> **why:** the canonical producer. It embeds the registry checksums, the card sha, the producer sha and the commit into every job and *refuses to start if any has moved* — the mechanism that makes a number traceable to the code that made it. Its binary sha `e54b27bb9e3f…` is contract **C-3**; it is named in `HF_RUN3_V1_RECORD.md`.

**`generation/producer/HeavyFlavourUtils.h`** · pipeline · **name frozen (G-recipe)**
> header-only · ← 18 files: the producer, every `Validation/` audit, the reduction, the decay-map builder
> **why:** the single definition of the physics conventions — `q_c = n_c − n_cbar` (contract **C-7**), `ClassifyHeavyStateDetailed`, the `kMultiplyHeavy` selector at `:357-359` that `GOLDEN_OUTPUTS.md` §2.9b-i cites by line. **The most-included file in the repository.** One definition, because two would disagree.

**`generation/producer/Sha256.h`** · pipeline
> header-only · ← 12 files
> **why:** self-contained SHA-256 so the producer and every validator can stamp and re-check digests without linking a crypto library into a Condor job.

**`generation/registries/GeneratedHeavyFlavourRegistry.h`**, **`GeneratedTuneSettingRegistry.h`** · pipeline
> `config/*.json` → C++ headers · ← producer, audits · ← generated by `tools/generate_registry_artifacts.py`
> **why:** the species and tune-setting tables are compiled *into* the producer so a job cannot run against a table it was not built for. Generated, never edited; `make registry` (**R1**) fails on drift.

**`generation/submit/runCondorJob.sh`** · operational tool · **name frozen (`Makefile`)**
> submit description → one job's raw file + receipt + `validate_raw_output.log`
> ← Condor → `setupEnv.sh`, `tools/campaign.py`, `Validation/validate_raw_output.sh`, `AuditOriginResolution.C`, `ListUnresolvedOrigins.C`
> **why:** the worker. It re-checks the pinned commit and producer sha *at execution time*, not at submission time, because the checkout can move in between — the failure that re-ran 2702 analysis jobs. It refuses to inherit `HADRONIZATION_BASE` from the environment, and `tests/test_recipe_scripts_executable.py` and the runner's `env -u` both assert that.

**`generation/submit/submit_status_analysis.sh`** · operational tool
> → renders and submits the analysis stage · → `tools/render_analysis_submit.py`, `tools/validate_analysis_outputs.py`, `Validation/validate_canonical_manifest.sh`
> **why:** the analysis-stage submit path, manifest-only and closed-environment.

**`generation/run_hf.sh`** · operational tool
> `{monash|junctions|closepacking}` → one local `hf_<mode>_<timestamp>.root`
> **why:** run the producer once, by hand, on a laptop. **It draws its seed from `$RANDOM`** and therefore cannot and must not feed a campaign — the seed ledger is what makes production seeds unique (**C-4**). A smoke-test convenience, correctly incapable of pretending to be production.

## 3. STAGE 3 — `merging/` — 3000 directories → 33 objects

**`merging/merge_root_files.sh`** · pipeline · **name frozen (`GOLDEN_OUTPUTS.md` §2.4)**
> 3000 validated per-job directories + sealed manifest → per tune: one central (1000 files) and **ten disjoint blocks** (100 each)
> ← `merging/make_subsamples.sh`, `tools/merge_supervisor.sh` → `MergeCanonicalAnalysis.C`, `tools/validate_analysis_outputs.py`, `tools/merged_pair_provenance.py`, both closure validators
> **why:** the merge driver, and **the whole statistical design**: `block = canonical_slot % 10`, ten disjoint exhaustive subsets of the *input files*, giving the SEM at dof 9. It validates before merging and refuses a tune set that is not equal-exposure and divisible by ten. Resumable by construction — it re-validates promoted legs rather than redoing them, which is why the reboot at 15/33 cost hours and not the campaign.

**`merging/MergeCanonicalAnalysis.C`** · pipeline
> per-job pair directories → merged pair directory · ← `merge_root_files.sh` → `MergeAnalysisObjects.C`, `GeneratedPairRegistry.h`
> **why:** merges against the *signed registry* rather than whatever objects happen to be present, so a missing pair is an error and not a silently shorter list.

**`merging/MergeAnalysisObjects.C`** · pipeline · **name frozen (`pair_file_object_contract_v1.json`)**
> object-level ROOT merge · ← `MergeCanonicalAnalysis.C`
> **why:** `hadd` becomes pathological on accumulated `THnSparse` objects. This is the safe fallback that adds them object by object.

**`merging/make_subsamples.sh`** · operational tool
> → delegates entirely to `merge_root_files.sh`
> **why:** a compatibility entry point for the older workflow. Its help text is the useful part: it records that **no random or bootstrap partition is permitted for paper inputs**, and names the two files that enforce it.

**This is the densest concentration of measurement-provenance in the tree.**
Seven of these eleven files are named in a `GOLDEN_OUTPUTS.md` recipe; their
names are frozen.

**`extraction/extract_species_decomposition.py`** · measurement-provenance · **R14 chain, name frozen**
> merged v3 directory → `per_species.csv`, `per_category.csv` (+ map-dependent `per_observable.csv`)
> ← `extraction/pipeline/tune_extract.sh`, `tools/reconstruct_deduplicated_decomposition.py`
> **why:** the reader that turns a merged directory into the decomposition tables — G14/G15's recipe. **Its `--decay-map` argument is required with no default**: the old default was the defective v1 map (`ERROR_RECORD.md` **E1**, 17.8 pp on D⁰), and no existing check caught it because all three maps carry the same ordinal digest and conjugation errors conserve the total exactly. Finding **F1**, fixed in the restructure session. It refuses a directory that is not exactly the registry's (finding A5, `tests/test_extraction_preflight.py`).

**`extraction/decompose_with_block_sems.py`** · measurement-provenance · **name frozen (anchor manifests)**
> central + ten blocks → decomposition with block SEMs, both conventions, I2/I3 integrity
> ← `harvest_tune.py`, `three_tune_table.py` → `compare_subset_parent.compare`
> **why:** **the harvest tool** — it produced the MONASH and three-tune central tables. It prints the block mean *beside* the pooled value so a material divergence is visible; the published estimator is the pooled one (review finding A10). Its exit status reports **I2 as well as I3** after finding A12 (`tests/test_decompose_exit_status.py`).

**`extraction/three_tune_table.py`** · measurement-provenance · **R14, name frozen**
> three run roots or committed anchors → the three-tune table on a common row set
> ← `plotting/paper/make_paper_figures.py`, `tests/test_three_tune_tables.py`
> **why:** **the resubmission's central number** (`THREE_TUNE_CENTRAL_TABLE.md`, FINAL 2026-08-16). Its stdout digest `a46a7f6b96f66817…` is pinned, and the test asserts every structural mean and SEM plus the partition/selection distinction in both directions. Regenerates from committed anchors alone — the remote run roots give the same bytes and are the origin, not a dependency.

**`extraction/compare_subset_parent.py`** · measurement-provenance · **R10/R10b, name frozen**
> two per-species tables → flagged bins at |z| > 4
> ← `decompose_with_block_sems.py` (as I2), `tests/test_compare_subset_parent.py`
> **why:** **E4's mechanism, kept as an executable test rather than as prose.** `null` is a **required keyword-only argument with no default anywhere** — I2 passes `mad`, the pinned E4 regression passes `binomial` by name, and neither caller can inherit a null it did not name. It carries a **σ̂ floor of 1.0** (without it, exactly-divided blocks gave σ̂ = 0.002 and 90 manufactured flags) and a calibration check that recovers σ̂ ≈ 1 on synthetic binomial data, which is what licenses reading 4.4 as "4.4× overdispersed".

**`extraction/apply_decay_map.py`** · measurement-provenance · **R7, name frozen**
> a decay map + per-species weights → the experiment-comparable regrouping
> ← `bbaryon_tune_advisory.py`, `tests/test_three_tune_tables.py`
> **why:** produces the map-v2 numbers of `MERGED_CONVENTION_TABLES.md` (D⁰ 25.2435 %…). Its particle/antiparticle ratio report is **advisory at |ratio−1| > 10 % and deliberately not a gate** — a hard gate at 1.00 would refuse real physics (Λ_c sits at 1.026).

**`extraction/second_branch_weight.py`** · measurement-provenance · **R8/R8b, name frozen**
> per-species weights (+ `--v2-map`) → the second-branch residual
> **why:** **the number was nearly withdrawn and this tool saved it.** Finding A8 established that the recipe as written printed the 12.84 % history row, not the published 0.0018 %, which then had no committed derivation. `--v2-map` implements it, and it was **confirmed rather than fitted**: one definition reproduces three published quantities at once — pre-split 5.7737 %, post-split 0.0018 %, and the B_c⁺/B_c⁻ split never quoted as a target. Quote **0.0017 %** against the E5-corrected table.

**`extraction/aggregate_m7.py`** · measurement-provenance · **R9/R9b, name frozen**
> ten block logs → the M7 unresolved-origin table
> ← `plotting/paper/make_paper_figures.py` (fig 2)
> **why:** reproduces both M7 halves from committed anchors. **Fail-closed below ten blocks and on mixed sectors** — a nine-block aggregate would silently produce a wrong SEM. It pools counts rather than averaging block ratios, which is the published estimator.

**`extraction/bbaryon_tune_advisory.py`** · measurement-provenance · **R15, name frozen**
> three run roots → per-tune b-baryon particle/antiparticle ratios
> **why:** step 2 of the advisory ladder (`STATE.md` PENDING 6). **`rc=0` always — it is an advisory and never fails**, so its exit status is deliberately not a verdict.

**`extraction/pipeline/harvest_tune.py`** · measurement-provenance · **name frozen (`GOLDEN_OUTPUTS.md` §2.9c)**
> one tune's merged output → closure verdict, extraction, integrity, decomposition
> ← `extraction/pipeline/tune_chain.sh`, `tests/test_harvest_tune.py`
> **why:** the per-tune harvest driver. It is how the JUNCTIONS and CLOSEPACKING schemas were verified — by **reading the emitted `analysis_schema=` value**, because the A4 expected-schema argument does not exist on the frozen Nikhef tree. **`harvest_tune.py` is the naming model this repository uses for tools:** verb, object, snake_case.

**`extraction/pipeline/tune_extract.sh`** · measurement-provenance · **name frozen (`GOLDEN_OUTPUTS.md`)**
> one tune's central + ten blocks → eleven `per_species.csv`
> **why:** runs the reader from a scratch deploy with its sha recorded, because the reader postdates the frozen checkout — the M7b pattern. The frozen checkout is **read for `setupEnv` only and never written**. `STATE.md` item 10 records the E5 trap being closed *at the path this script actually calls*, which was not the path anyone was looking at.

**`extraction/pipeline/tune_chain.sh`** · operational tool
> waits for ten promotions → closure → extraction, chained server-side
> **why:** so the waiting costs the session nothing. **Deliberately not relaunched** for the current merge (`STATE.md` item 11): the merge runs closure itself with a *stronger* invocation, and relaunching would recreate the CPU contention that caused the band MISS.

## 5. STAGE 5 — `plotting/` — figures

### 5.1 The paper figure generator — deterministic by construction

**`plotting/paper/make_paper_figures.py`** · measurement-provenance · **R13/R13b, name frozen**
> committed anchors → `fig1_species_decomposition.svg`, `fig2_m7_inclusive_shift.svg`, `fig3_multiplicity_classes.svg`
> → `three_tune_table.py`, `aggregate_m7.py`
> **why:** **generated from committed tables by script, with no hand steps.** `--figure ossvsmult` **fails closed** rather than drawing a placeholder — a figure with invented data is worse than a missing figure, because a figure travels further than its caption. Fig 3 *recomputes* the published percentile table rather than displaying it, agreeing to < 0.01 pp on all eleven classes.

**`plotting/paper/svgkit.py`** · measurement-provenance · **name frozen (`GOLDEN_OUTPUTS.md` §2.12)**
> → byte-deterministic SVG
> **why:** **it has no dependencies at all, and that is the point.** matplotlib's bytes move with its own version, with freetype and with the installed fonts, so a pinned digest would fail on a different machine for reasons unrelated to physics. Every coordinate goes through one fixed-precision formatter, making the bytes a pure function of the input numbers.

## 6. `Validation/` — ROOT audits and closure

**The six unrun macros in this directory are the most valuable files in it and
the easiest to mistake for dead ones.** `STATE.md` gives them a category of
their own: *written — unrun — available*. This is the same shape as M7, which
sat unrun until a reviewer asked and then took one session to become a table
with an uncertainty.

### 6.1 On an automated path · pipeline

### 6.2 Run at scale · measurement-provenance

**`Validation/MeasureUnresolvedSystematic.C`** · **name frozen (`REPRODUCIBILITY.md`)**

## 9. `tests/` — 46 files, and the acceptance gate

**`tools/run_tests.sh:38` globs `tests/test_*.py`, so membership is by pattern,
not by name.** A test with zero references is normal here, and reference count
is worthless as a liveness signal in this directory.

**The dominant convention: a test names the defect it closes.** Most docstrings
open with `THE DEFECT THIS CLOSES` or `THE DEFECT (review finding A_n)`. That
makes the suite a second, executable copy of the error record — and it is why
deleting a test deletes evidence.

**The second convention, from 2026-08-18: a test for a fail-closed guard must be
mutation-checked before it is believed.** E2 is the reason — a hook-certification
harness that deleted its own hook and then printed "CORRECT" twice, because the
"refused" direction passed on an absence. A guard test asserts that something
does *not* happen, and that assertion passes just as cheerfully when the
mechanism under test is missing, misspelled or never invoked. Passing therefore
proves nothing on its own.

So: break the mechanism deliberately, confirm the test fails, restore it, confirm
it passes — and record the mutation and the count of assertions it broke in the
commit message, where a reviewer can see the test had teeth without re-running
it.

## 12. NAMING — the rule this pass derived, and the one rename it did not do

The brief's rule is *compact, functional, verb-first `snake_case` for tools; no
`improved`/`new`/`final`/version qualifiers; code only, because artifacts appear
in recorded provenance and renaming them falsifies the record.*

**Applying it required extending the exemption, because in this repository the

### 12.1 Renames executed: none — and that is the finding

The 134 rename-eligible files were reviewed against the rule. **Not one carries
a banned qualifier or a non-functional name.** `tests/` follows
`test_<subject>.py`, `plotting/` follows `Plot_<What>_<How>.C`, `Validation/`
follows `Validate*`/`Audit*`/`Test*`, and `tools/` is already verb-first where
it is a tool and noun-first only where it is a library (`campaign.py`) or a
reporter (`campaign_status.py`). The long `PtMultiplicity/` names encode

**artifact's** version, not the code's, and v1.1 and v2 are separate published
maps with separate recipes (§8.1).

### 12.2 The exception, priced rather than performed

**`plotting/improvedPlotting_THnSparse.C` is the one name that violates the
rule, and it is in the frozen group.** The cost of renaming it, measured:

1. **The rename forces a byte change.** ROOT's convention ties the entry-point
   function to the basename (`int improvedPlotting_THnSparse(const char*)` at
   `:5030`), and the macro embeds its own filename at `:385` and `:1334` for
   repo-root detection. A file-only rename would leave the old function name
   inside the new file — worse than the defect.
2. **Its sha256 is live recorded provenance.**
   `tools/statistical_robustness.py:669` checks **every**
   `multiplicity_boundary_receipt_v1.json` against
   `sha256(plotting/improvedPlotting_THnSparse.C)`. The shipped three-tune
   canvas's receipt records `6dace202…`. Changing the bytes does not re-pin a
   digest — **it invalidates committed receipts for a figure rendered on
   2026-08-16.**
3. **Two further pins move with it:** `config/multiplicity_class_boundaries_v1.json`
   names it in the `single_definition_note` that forbids a second copy of the
   axis, and `docs/plotting_validation/hf_run3_v1_threetune_20260816/RUN_RECORD.md`
   records it as the plotter source.
4. **The figure set is not frozen.** The merge campaign is still inside its own
   closure pass and the freeze stands.

**Recommendation (owner's call, §11 Q5):** rename to
`plotting/Plot_PairBalancing_THnSparse.C` — matching the sibling
`Plot_<What>_<How>.C` convention — **in a dedicated commit after the figure set
is frozen and the campaign is recorded COMPLETE**, re-rendering the canvas so
the receipt and the run record are regenerated rather than patched. Doing it
during a triage pass would mean editing a provenance record to accommodate a
cosmetic change, which is the one thing this repository's contract is built to
prevent.
