## 5. WHAT THE MOVES BROKE, AND HOW IT WAS FIXED

**Path references were rewritten across ~120 live files.** Two are worth naming.

### 5.1 A frozen artifact was almost silently changed — the digest caught it

The bulk rewrite changed `"category_source"` inside
`AnalysisScripts/species_ordinals_v2.json` from `SimulationScripts/…` to the new
producer path, moving **G1's digest from `ccec0dbc…` to `60a2c6f2…`**.

**That field is a provenance record of where the classifier lived when the table
was built — not a live path — and the artifact is frozen.** Reverted; G1 is
byte-identical. `tools/GenerateSpeciesOrdinals.C` still emits the original
string, so a future regeneration still reproduces `ccec0dbc…`.

> **This is the freeze contract doing exactly its job.** A mechanical rewrite
> that was correct 119 times out of 120 was wrong once, in the one file where
> being wrong would have invalidated every downstream digest — and the recorded
> digest is what noticed.

### 5.2 The D4 override created three `../` includes

Moving the reduction and merge macros while their contract headers stayed in
`AnalysisScripts/` turned three sibling includes into `../AnalysisScripts/`
includes, in `analysis/status_analysis_THnSparse_qq.C` and
`merging/MergeCanonicalAnalysis.C`. **A cost of the override, not a defect.**

### 5.3 One pinned checksum was legitimately re-pinned

`config/statistical_robustness_v1.json`'s `boundary_configuration_sha256`, because
the rename changed `write_path` values inside the plotting configuration it pins.
**The pin exists to notice exactly that kind of content change**, so it was
updated in the same commit as the rename that caused it —
`6c1f33b7…` → `6bfeb9a6…`.

## 7. THE 2026-08-17 TRIAGE PASS — delta: ZERO ROWS

**The publication triage pass re-walked all 219 tracked executables against the
naming rule and executed no rename.** That is a measured result, not an omission,
and it is recorded here so the next pass does not re-derive it.

### 7.1 The rule the pass had to extend, and why

The standing rule exempts **artifacts** from renaming, because they appear in
recorded provenance and renaming them falsifies the record. **Measurement showed
the same argument covers a third of the code.**

| | count |
|---|---|
| executables named inside a `GOLDEN_OUTPUTS.md` recipe, a run record, an anchor `MANIFEST.md`, a signed `config/*.json`, `REPRODUCIBILITY.md`, `Paper/**` or the `Makefile` | **67** |
| not so named — rename-eligible | **134** (51 of them `tests/`) |

**A code file in the first group has a name that is load-bearing provenance.**
Renaming it edits a document whose text *is* a reproducibility claim.
`docs/COMPONENTS.md` marks every such file **name frozen**.

### 7.2 Nothing in the eligible 134 was mis-named

Reviewed against *compact, functional, verb-first `snake_case`, no
`improved`/`new`/`final`/version qualifiers*: `tests/` follows
`test_<subject>.py`, `plotting/` follows `Plot_<What>_<How>.C`, `Validation/`
follows `Validate*`/`Audit*`/`Test*`, and `tools/` is verb-first where it is a
tool and noun-first only where it is a library or a reporter.

**One clarification worth fixing in the rule itself:** `build_decay_parent_map_v2.py`
names the **artifact's** version, not the code's. v1.1 and v2 are separate
published maps with separate recipes (R5, R6) and both builders are live. A
version qualifier that identifies *which published artifact a tool produces* is
functional and stays.

### 7.3 The one violation, priced and deferred

**`plotting/improvedPlotting_THnSparse.C`** carries a banned qualifier and is in
the frozen group. Renaming it forces a byte change — ROOT ties the entry-point
function to the basename, and the macro embeds its own filename twice — and its
sha256 is checked against **every** `multiplicity_boundary_receipt_v1.json` by
`tools/statistical_robustness.py:669`. Changing the bytes does not re-pin a
digest; it **invalidates committed receipts for a figure rendered on 2026-08-16**.

**Deferred with a written recommendation** (`docs/COMPONENTS.md` §12.2): rename
to `Plot_PairBalancing_THnSparse.C` in a dedicated commit after the figure set
is frozen, re-rendering so the receipt is regenerated rather than patched.

> **This is §5.1's lesson pointing the other way.** There, a mechanical rewrite
> that was right 119 times out of 120 was caught by a recorded digest. Here the
> digest is doing the same job *before* the edit: it prices the rename honestly,
> and the price is higher than the tidiness is worth while the campaign is open.
